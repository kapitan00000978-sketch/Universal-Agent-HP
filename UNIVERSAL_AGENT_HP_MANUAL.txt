  • Optional: Docker (for air-gapped Docker sandboxing)
  • Optional: Local generative LLM runner (Ollama/LM Studio); Laya is a typed-decision model, not a chat LLM.

  • TELEGRAM_BOT_TOKEN  : Telegram bot token (if running in Telegram mode)
  • SERVER_PORT         : Default is 8000
  • COGNITIVE_BUDGET    : Maximum USD budget before safety alerts (default: 5.00)

3. LAUNCHING UNIVERSAL AGENT HP (RUN MODES)
================================================================================
Universal Agent HP provides three unified entry points via `run.py`:

MODE A: WEB CONTROL PANEL (Recommended for UI & Visualization)
  Command:
    python run.py
  Description:
    Launches FastAPI server and automatically opens browser at http://localhost:8000.
    Features live chat, staff roster, DAG visualization, model routing breakdown,
    tool reliability telemetry, and knowledge graph viewer.
  Flags:
    --port <port>       : Custom port (e.g. python run.py --port 8080)
    --no-browser        : Suppresses automatic browser launch

MODE B: INTERACTIVE CLI (Recommended for Terminal Power Users)
  Command:
    python run.py --cli
    # OR directly:
    python cli.py
  Description:
    Launches rich interactive command prompt with streaming output, hotkeys,
    and slash commands (/help, /clear, /status, /model, /tools, /dag).

MODE C: TELEGRAM BOT (Remote Agent Assistant)
  Command:
    python run.py --telegram
  Description:
    Runs the Telegram daemon connecting to the configured TELEGRAM_BOT_TOKEN.
    Allows talking to Titan, checking system status, running commands, and receiving
    notifications directly from your phone.

5. COGNITIVE REASONING STRATEGIES & PLANNING ENGINES
================================================================================
Universal Agent HP offers six distinct reasoning engines:

1. STANDARD (ReAct Loop):
   Ideal for quick lookups, simple edits, and single-file modifications.

2. TREE OF THOUGHTS (ToT):
   Generates multiple parallel branching hypotheses, scores them, and selects the
   optimal trajectory.

3. MONTE CARLO TREE SEARCH (MCTS):
   Four-phase loop: Selection -> Expansion -> Simulation -> Backpropagation.
   Best for formal algorithmic problems and game-tree explorations.

4. MULTI-AGENT DEBATE:
   Spawns two adversarial agents:
     • Advocate (proposes thesis and architecture)
     • Skeptic (identifies edge cases, security flaws, race conditions)
     • Judge/Arbitrator (synthesizes the winning compromise)
   Tool: debate_solve(question, rounds)

5. REFLEXION LOOP:
   Autonomous self-critique engine:
     Initial Solution -> Self-Critique Evaluation -> Refined Solution.
   Iterates up to 3 cycles until score meets threshold.
   Tool: reflexion_solve(task)

6. TASK GRAPH (DAG) PLANNER:
   Uses topological sort and Kahn's algorithm to compute dependency waves.
   Independent tasks execute concurrently (`max_concurrency=4`).
   If a task fails, performs selective replanning on only downstream nodes.
   Tool: dag_plan_and_run(goal), dag_visualize(goal)

6. KNOWLEDGE GRAPH MEMORY & AST INTEL
================================================================================
Titan maintains a persistent causal and structural graph of the workspace:

CAPABILITIES:
  • AST Workspace Indexer: Automatically parses Python source files, extracting
    classes, functions, inheritance hierarchies, and import dependencies.
  • Causal Fact Graph: Stores semantic associations, constraints, and operational rules.
  • Blast Radius / Impact Analysis: Before editing a function or file, calculates
    all downstream callers and affected components to prevent unintended breakage.

TOOLS:
  • kg_query(entity_id, depth)        : Queries multi-hop relations around an entity.
  • kg_impact_analysis(entity_id)     : Calculates affected blast-radius.
  • kg_add_fact(source, rel, target)  : Inserts semantic relationship.
  • kg_index_workspace(max_files)     : Scans AST of workspace files into graph.

7. MODEL ROUTER & COGNITIVE BUDGET MANAGEMENT
================================================================================
Prevents prompt token waste while ensuring high-complexity tasks get elite reasoning:

MODEL TIERS:
  1. FAST_CHEAP (e.g. gpt-4o-mini, gemini-1.5-flash, claude-3-5-haiku):
     Lightweight tasks: summaries, file reads, formatting, status checks.
  2. STANDARD_CODING (e.g. claude-3-5-sonnet, gpt-4o, deepseek-coder):
     General software engineering, API development, refactoring, test suites.
  3. DEEP_REASONING (e.g. o3-mini, deepseek-reasoner, o1):
     Architectural trade-offs, formal logic, multi-agent debates, race condition debugging.

DYNAMIC FAILURE ESCALATION:
  If a task fails or triggers retries, the router automatically escalates:
    FAST_CHEAP  -->  STANDARD_CODING  -->  DEEP_REASONING

COGNITIVE BUDGET:
  Tracks cumulative input/output tokens and real-time USD expenditure.
  Emits safety warnings when budget limit is approached.

TOOLS:
  • model_route(task, prior_failures) : Recommends optimal tier and pricing estimate.
  • model_budget_status()             : Renders token spend and USD expense report.

8. EXECUTION SANDBOX, ISOLATION & ZERO-LOSS ROLLBACK
================================================================================
Guarantees that exploratory or unsafe code never damages your host workspace:

FILESYSTEM SNAPSHOTS:
  • Captures point-in-time byte snapshots of all workspace files up to 5 MB per file.
  • Automatically ignores transient dirs (.git, .venv, __pycache__, node_modules).
  • Computes SHA-256 integrity hashes and structured diffs (added/removed/modified).

TRANSACTIONAL ROLLBACK:
  • Modified files are reverted to exact original bytes.
  • Deleted files are recreated.
  • Malicious or newly created temporary files are safely removed.

SAFE RUNNER & SECURITY SCREENING:
  • Scans code before execution, blocking dangerous patterns:
    - Fork bombs (:(){ :|:& };:)
    - Root / disk wiping (rm -rf /, format C:)
    - Destructive file deletion calls
  • Subprocess isolation with strict timeout enforcement (default: 30s).
  • Auto-Rollback: If script crashes or times out, instantly reverts all changes.

TOOLS:
  • sandbox_execute(code, language, timeout, rollback_on_failure) : Executes code safely.
  • sandbox_snapshot_create(name)    : Captures named workspace snapshot.
  • sandbox_snapshot_rollback(name)  : Restores workspace to snapshot state.

9. DRIFT DETECTION & PERFORMANCE MONITORING
================================================================================
Monitors agent quality over time to detect regressions and performance decay:

TELEMETRY TRACKING:
  • Logs task ID, timestamp, domain category, success/failure, step count,
    latency duration, tokens used, and failing tools.
  • Persists to `.titan/drift_metrics.json`.

SLIDING-WINDOW COMPARATIVE ANALYSIS:
  • Compares recent window of N tasks against historical baseline.
  • Detects:
    - Success Rate Drop (>= 20% -> WARNING, >= 35% -> CRITICAL).
    - Step Inflation (>= 1.8x -> detects exploratory thrashing / infinite loops).
    - Latency Degradation.

ROOT-CAUSE DIAGNOSTICS:
  • Identifies which tools fail most frequently.
  • Issues actionable mitigation advice (e.g. upgrade model tier, activate DAG planner).

TOOLS:
  • drift_record_task(...)           : Logs execution telemetry.
  • drift_check(window_size, drop)   : Analyzes health and returns drift report.
  • drift_status()                   : Shows cumulative success rate and metrics.

   Synthesizes system prompt refinements incorporating lessons learned as unified diffs.

3. LESSON CRYSTALLIZATION:
   Permanently saves distilled insight into:
     • SkillRegistry: Saved as auto-injected playbook in `skills/`.

4. REGRESSION EVAL BENCHMARK SUITE:
   Automated regression suite verifying coding, reasoning, security, and git tasks.
   Calculates pass rate, average quality score, and execution duration.

11. MANDATORY AGENT RULES OF ENGAGEMENT (OPERATIONAL LAWS)
================================================================================
The following rules MUST be followed by the agent at all times during operation:

LAW 1 — ZERO DATA LOSS:
  Before performing any bulk modification or high-risk refactoring, the agent MUST
  take a snapshot using `sandbox_snapshot_create`. If an error occurs, it MUST
  rollback or heal the corrupted state.

LAW 2 — READ BEFORE EDITING:
  The agent must NEVER blindly edit a file without first viewing the relevant lines
  or checking its AST relationships.

LAW 3 — SURGICAL MODIFICATION OVER BLIND OVERWRITES:
  For Python code, prefer `ast_patch_file` or targeted diffs over full-file
  overwrites to prevent indentation or syntax breakages.

LAW 4 — CONTEXT EFFICIENCY:
  Do not overload system prompts with all 60+ tool schemas. Use `tool_discover`
  or dynamic domain bundles to inject only relevant tools.

LAW 5 — ESCALATE ON REPEATED FAILURES:
  If a task fails on FAST_CHEAP model tier, do not loop endlessly on the same tier.
  Escalate to STANDARD_CODING or DEEP_REASONING via `model_route`.

LAW 6 — CONCURRENT INDEPENDENCE:
  Tasks that do not depend on each other MUST be planned via DAG and executed
  in parallel waves to maximize performance and minimize turnaround time.

LAW 7 — PERMANENT LEARNING:
  When a novel error is encountered and resolved, the resolution MUST be crystallized
  via `self_improve_crystallize_lesson` so future tasks benefit immediately.

12. TROUBLESHOOTING & FREQUENTLY ASKED QUESTIONS
================================================================================
Q1: Web UI does not start or port 8000 is occupied.
A1: Launch on another port:
    python run.py --port 8085

Q2: How do I run Titan locally without external API keys?
A2: For full chat and code generation, install/start a local generative model with Ollama or LM Studio.
    Laya and Laya-MLX provide local typed decisions (choice/score/yes-no), not chat generation.
    Install `pip install -e '.[laya]'` or, on Apple Silicon macOS, `pip install -e '.[laya-mlx]'`.
    Then call `laya_decide` or run `python -m titan_agent.laya_decisions` with a question JSON file.

Q3: A command modified files incorrectly. How do I revert?
A3: If you captured a snapshot:
    python cli.py --meta "/rollback <snapshot_name>"
    Or via tool:
    sandbox_snapshot_rollback(name="<snapshot_name>")

Q4: How do I run the full self-test suite to verify system integrity?
A4: Run pytest across the whole repository:
    python -m pytest tests
    Expected output: 600+ passed, 0 failures.

Q5: How do I check current token and financial expenditure?
A5: Use the budget status tool:
    python cli.py "/model"
    Or programmatically call `model_budget_status()`.
